## 3. 本轮关键改造

1. 现场派驻与 `ShiftSchedule` 对接，以人员+工作日保持唯一。项目经理按负责项目及直属/已有项目人员管理，员工只看到本人派驻。
2. 总览从派驻计划计算应到人数，显示上下班打卡事实与考勤异常；不把未打卡直接称为旷工，也不将已有打卡称为当前在场。
3. 必拍照片独立于 GPS 是否合格进行校验；实际打卡照片必须引用本人上传的文件。照片缺失按原引擎异常记录机制处理；手机端必拍时先要求拍照。
4. 固定跨夜班在结束时间后四小时内仍归属开班日，超过这一窗口回到当日；有单独回归测试。
5. 月锁定对底层记录、原始打卡、排班和考勤影响写入增加统一保护；保留历史查询。
6. 动态补卡提交接入资格计算，校验本人身份、卡点、时段、重复待审与月次数。动态考勤申请不能通过额外 `employee_id` 字段影响他人。
7. 撤回审批同时取消待处理任务；动态请假/加班的审批单 ID 不再误当作旧业务表 ID。
8. 文件增加所有者记录和下载鉴权。允许所有者、系统/售后管理员以及具有相应审批查看关系的人员访问；项目经理只按项目关系读取现场打卡照片。
9. 模板个人草稿独立保存，不覆盖发布模板；原发布版本和在途实例快照继续保留。
10. 去除工资条、聊天、招聘等手机入口和未部署的预置模板；修复重复底部导航、模板“保存于1分钟前”的固定文案及真实 TypeScript 检查。
11. 定位服务与浏览器地图 Key 分开配置；IP 定位不进入打卡坐标。未配地图时基础演示规则仍可打卡。
12. 原考勤重算 dirty 队列增加实际消费者，按日重算并刷新月汇总；锁定月份等待解锁后重试，失败原因可查。

13. 同时缺卡和迟到/早退的月汇总保留各项异常计数，现场总览也不再因主状态是缺卡而漏计迟到；隔离数据库回归覆盖该组合。
14. 按补充要求恢复 EHR 原版手机首页、工作台、个人中心、通知和团队页，以及管理端框架；补接自助资料/余额接口，团队统计限定到项目管理范围。详见 [原版 UI/UX 沿用与核对](08-原版UIUX沿用与核对.md)。

## 5. 初始模板的业务边界

请假、加班、外出、出差、补卡保留原审批到考勤的业务事件和影响处理。请假与补卡的实写链路已在隔离数据库验证。

派驻申请、现场调换、陪产日报、撤场申请是可发起、可审批、可留档的通用表单。派驻/调换/撤场通过后由项目经理在“项目与派驻”明确办理，系统不凭自由文本项目名称自动调整排班。后续可增加 ID 型业务绑定。

补卡策略由管理员在考勤规则中打开和配置；不能因为有一个补卡模板就绕开考勤规则限制。个人模板草稿按“本人+模板”隔离，新模板草稿使用本人的一个临时槽位；多人同时修改发布配置暂没有乐观锁编辑提示。

## 6. 仍保留的边界

- 同一人员同一天一个现场/班次；同日跨多个现场、多段派驻不是本轮基本模型。
- 时区按中国标准时间处理，非全球多时区系统。
- 尚未做真实手机 GPS/相机与网络波动验收；定位服务需要自己的腾讯地图配置和 HTTPS。
- 部署配置已提供，本轮未启动 MySQL 容器验证或公网部署；不能将本地 SQLite 测试等同于生产验收。
- 后台任务当前按单 API 进程运行，未配置多进程任务争抢锁；多实例部署前需独立任务执行器。
- 原模型关联仍需要部分 HR 兼容表与代码。未导入历史业务数据，不提供整个人事薪资系统的产品入口。
- 原引擎不支持嵌套并行节点，不能发布成可运行流程。外部连接器、公式编辑等原本未接入的高级选项不算已实现能力。
- 历史草稿/版本/日志保存已实现，但这不是完整企业级电子签名、不可篡改证据归档或持续在场证明。
- 原生 APK/IPA、企业微信单点登录、客户确认门户、门禁硬件、AI识别与工资结算属于候选池，未作为本轮基础版验收内容。

## 7. 推荐体验顺序

1. 管理员进入“人员与权限”，查看项目经理及工程师的直属主管关系。
2. 查看“项目与派驻”的客户、项目、现场与本周安排。
3. 在“考勤管理→考勤规则”检查现场规则，再按实际需求设置定位与照片。
4. 用工程师账号打开手机端打卡、发起陪产日报或请假。
5. 用项目经理账号打开手机审批并处理，再回总览/报表查看结果。
6. 管理员编辑模板、保存草稿，刷新重新打开，通过“继续草稿”恢复；检查后发布。
7. 使用“业务事件”和“操作日志”核对回写及关键操作。
