## 花名册与账号流程

管理端“人员花名册 → 导入花名册”：下载模板、上传、核对预览、确认导入、查看逐行结果。支持 `.xlsx`、`.xls`、`.csv`，单次最多 5 MB、1000 人；读取第一个工作表，允许前面有标题行，前十行内须找到姓名和手机号表头。

| 字段 | 处理规则 |
|---|---|
| 姓名、手机号 | 必填。手机号按文本读取，兼容 Excel 数字单元格和 +86 前缀 |
| 工号 | 可选；新员工留空时生成 `AF-手机号`，已有员工留空保留原工号 |
| 岗位 | 可选；已有员工的空值不覆盖原岗位 |
| 在职状态 | 新员工默认在职；在职/试用可启用，待入职/离职/停用不可登录 |
| 企微账号 | 可选；必须是企微通讯录中的 userid，绑定前先设置企业 CorpID |

预览不写入数据库。确认时重新解析并校验文件；正确行导入，错误行保留原因供修正。重复导入按手机号匹配，不重设密码、不提升角色、不重新启用停用账号。新员工只授予“售后人员”。手机号相同但姓名不同、工号冲突、重复手机号或企微绑定冲突均列为错误，不猜测人员身份。系统管理员账号通过人员编辑维护，不能通过花名册改写。

权限和直属主管由人员编辑维护；部门、派驻、现场、班次、规则和审批模板继续使用原业务界面。人员启停是立即生效的本系统访问控制，不等同于连续在场判断。

## 正式登录的校验顺序

1. 企微内通过网页授权，电脑浏览器通过企微 Web 登录页面扫码/授权。
2. 后端用本企业自建应用凭证换取成员 userid；不信任浏览器提交的手机号、姓名或角色。
3. 查询企业成员状态和应用可见范围，校验应用启用状态、可见成员/部门（含子部门）/标签；非企业成员、互联企业成员、未激活、禁用、退出或不在范围内的成员均拒绝。
4. 按 `CorpID + userid` 找到本系统绑定的在职员工；没有花名册绑定不得自动开户。
5. 手机端按角色展示入口；管理端另外要求系统管理员、售后负责人或项目经理权限。每个业务 API 继续校验角色/数据范围。

userid 按企微规则不区分大小写；系统存储规范化小写。一个成员只能绑定一个本系统员工。企微账号列留空不会解除现有绑定；在人员编辑中显式清空可解除绑定。修改绑定、员工停用或离职后，本系统后续请求会拒绝旧会话。

OAuth state 五分钟有效、单次消费，并与本浏览器保存的随机校验值和手机/管理端类型绑定；回调地址固定取服务端配置，不接受任意跳转 URL。授权码在页面初始化时从浏览器地址记录中移除。企微会话当前有效 15 分钟，过期后重新企微认证；只在企微侧移出/停用的变化会在下一次认证时校验，现有会话最多保留至到期。本系统停用或修改绑定则下一次请求即时生效。

## 后续接入配置

暂不需要现在提供。后续具备域名和自建应用后，在后端配置：

```dotenv
LOGIN_MODE=wecom_only
WECHAT_CORP_ID=企业ID
WECHAT_AGENT_ID=应用AgentID
WECHAT_SECRET=应用Secret
WECHAT_WEB_REDIRECT_URI=https://实际域名/login
WECHAT_MOBILE_REDIRECT_URI=https://实际域名/mobile/login
```

开发环境执行 `./scripts/setup.sh --admin` 可初始化 `admin / admin123`；已有账号不会被初始化覆盖。生产环境没有默认管理员口令。

Secret 仅保存在本机/服务器环境配置，不进入前端、截图、源码或日志。企微后台配好应用主页、可信域名、企业可信 IP、可见范围及读取成员所需权限。所有回调必须为可达 HTTPS；本机 `127.0.0.1` 用于开发验收，不能直接作为手机端正式地址。

本机 `LOGIN_MODE=password`；联调时可设 `hybrid`。正式环境同样支持 `password`；如果选择 `wecom_only`，则必须提供完整企微配置。仅企微模式关闭两个密码登录 API，并拒绝之前签发的密码会话，不只是隐藏登录表单。

首次生产初始化需通过进程环境传入 `ADMIN_PHONE=admin`、自定 `ADMIN_PASSWORD`；仅企微模式额外传入 `ADMIN_WECOM_USERID`，执行 `python -m app.bootstrap --admin`，同时完成管理员的企微绑定，避免只开企微入口却没有可登录管理员。初始化不会自动替换已有管理员账号。
