## 抽取时必须一起处理的依赖

| 对象 | 应保留的最小依赖 | 需要拆开的依赖 |
|---|---|---|
| 打卡/规则/排班 | 人员、组织、地点、日历、文件、规则日志、申请资格 | 薪资费率及调休余额副作用改为可选适配器 |
| 审批引擎 | 组织与负责人解析、模板版本、任务、动作、委托、通知、文件、业务事件 | `_sync_business_status` 中招聘、薪资、离职等分支拆成按业务注册的处理器 |
| 考勤影响 | 事件出站表、消费去重、影响表、补卡流水、重算与月报 | 请假余额消费者与售后现场状态不能混为一体 |
| 管理端 | 考勤页、审批页、流程画布、人员选择、请求封装、角色守卫 | 不能把整个 HR 菜单与完整员工隐私档案搬入 |
| 移动端 | 打卡、发起表单、审批详情、审批中心、团队考勤、定位工具、文件和通知 | 聊天、工资、招聘、资产入口按清单选装 |
| 数据库 | 独立数据库、迁移、基础角色、模板和规则种子 | 旧 Alembic 全量历史包含 HR 表，须整理依赖或生成独立基线；不能无选择执行 |
| 部署 | 后端、PC 静态站点、H5、独立数据库及文件卷 | Compose 文件没有内置生产数据库；须补齐新系统部署，不继承生产凭据 |
