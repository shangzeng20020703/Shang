# 部署与维护

## 本地运行

执行根目录 `scripts/setup.sh`，然后 `python3 scripts/dev.py start`。本地依赖安装完成后无需每次重新安装。`stop` 只停止该脚本登记且命令仍属于本项目的进程，不根据端口号强制结束其他程序。

本地配置为 SQLite，数据和上传文件分别存放在 `backend/data`、`backend/uploads`，均不进入源码包。本机指定账号见 README；新增人员默认初始密码按要求为 `585858`，自设密码至少 8 位。正式环境支持花名册手机号密码登录；企微登录可选，参见 [账号与企微接入](09-账号花名册与企微入口.md)。

## 首次无演示数据初始化

```sh
cd backend
# 将 ADMIN_PHONE、ADMIN_PASSWORD 通过当前运行环境提供；密码至少 8 位；选择企微登录时另传 ADMIN_WECOM_USERID 绑定企微管理员。
.venv/bin/python -m app.bootstrap --admin
```

`--admin` 初始化管理账号与基础模板；`--demo` 才额外创建演示人员、客户、项目、现场、派驻。生产环境拒绝 `--demo`。

`app.bootstrap` 当前版本为 8，在既有人员项目参与区间及考勤分段表基础上增加系统配置表；既有安排和历史考勤不删除。更新前备份数据库，执行 `python -m app.bootstrap` 后再启动；旧版未升级数据库会被后端明确拒绝启动。后续版本若更改已有表结构，应增加明确的迁移脚本，而不是依赖 `create_all` 自动更改列。

## 配置与数据范围

- 配置文件：`backend/.env`，格式参考 `.env.example`。
- `ENVIRONMENT=production` 时必须提供随机 `SECRET_KEY`；手机号密码模式设 `LOGIN_MODE=password`，仅企微模式须选择 `wecom_only` 并提供完整企微配置。
- 腾讯地图 WebService Key 仅在服务器环境变量配置；浏览器 Key 可通过环境变量 `TENCENT_MAP_BROWSER_KEY` 设置回退值，或通过管理员专用后端接口 `GET/PUT/DELETE /api/v1/system-settings/tencent-map` 管理数据库覆盖值。管理端不显示配置入口或页面。数据库保存值优先于环境变量，清除覆盖值后回退。保存后刷新已打开的手机端地图页，无需重启后端。浏览器 Key 会供手机端 SDK 使用，应在腾讯控制台加入实际 Web 域名限制；GPS 围栏采用腾讯地图坐标口径，真实定位使用 HTTPS。
- 浏览器网页不能稳定读取 Wi-Fi SSID 或证明设备没有模拟定位。此类字段保留兼容能力，不表示已经完成原生设备可信采集。
- 来源身份取登录账号；相机、位置和文件绑定用于记录与规则判断，不是持续在场证据。
- 项目经理通过现场管理接口只能安排本人、直属人员或负责项目已有人员。跨部门新人员可由管理员先派驻或调整主管关系。
- 草稿按登录管理员本人隔离；版本发布仍使用原模板管理权限。

## Docker / MySQL 部署材料

MySQL 8.4、API 和网页容器已通过本机独立空库验收；首次生产发布需再次执行下方登录与隔离检查。

1. 将 `deploy/.env.example` 复制为 `deploy/.env`，填入随机数据库口令、随机会话密钥、企微配置及自己的地图配置。
2. 执行 `docker compose --env-file deploy/.env -f deploy/compose.yaml up -d db`，等待数据库健康。
3. 通过当前环境提供初始化管理员信息，执行 `docker compose --env-file deploy/.env -f deploy/compose.yaml run --rm -e ADMIN_PHONE -e ADMIN_PASSWORD -e ADMIN_WECOM_USERID api python -m app.bootstrap --admin`，创建表和管理员；更新既有数据库时只执行不带 `--admin` 的 bootstrap。API 启动前必须完成当前版本的 schema 初始化。
4. 执行 `docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build`。
5. 默认只绑定本机 `127.0.0.1:8180`。在外层配置 HTTPS 域名反向代理后，手机浏览器才能访问并可靠使用位置/相机能力。
6. API 只运行一个进程；后台 outbox 和考勤重算随 API 启停。扩为多实例前拆分任务执行器并增加任务领取锁。
7. 依次验证登录、建规则/现场/派驻、真实手机定位与拍照、审批回写、报表、文件下载权限及重启数据保存。

Nginx 将所有 `/uploads/` 请求转发给 API 鉴权，不直接暴露文件目录，也不记录含临时 token 的文件 URL。部署源码包没有携带本机 `.env`、会话密钥、数据库或上传文件。

## 备份与恢复

SQLite 本地运行时，最直观的完整备份方式：先 `python3 scripts/dev.py stop`，复制 `backend/data` 与 `backend/uploads` 到备份位置，再重新启动。需要不中断服务备份时应使用 SQLite backup API，不直接复制正在写入的主数据库文件。

MySQL 通过数据库逻辑备份/快照保存，并一同备份上传卷；同时安全保存部署配置和密钥。恢复后必须验证人数、派驻数、审批历史、报表和附件可读性。不要用演示初始化覆盖导入的业务库。

## 日常诊断

- `http://127.0.0.1:8186/health` 实际检查数据库连接。
- `.runtime/api.log`、`.runtime/web.log`、`.runtime/mobile.log` 为本地启动日志。
- 管理端“业务事件”可查 outbox、消费记录、考勤影响和重算任务，允许按原服务规则重试失败事件。
- “操作日志”提供只读审计查询；新现场模块的写操作会记录操作人、对象和结果。
- 锁定月份的重算任务保持等待状态，管理员按既有业务流程解锁后重试；已锁定历史不应静默被新计算覆盖。
- 构建中的体积警告和 Python `crypt` 弃用警告已记录，它们不等同于构建/业务测试失败。

## 后续提取与集成

后端仍保留部分旧模型、服务和兼容表，因为人员 ORM、公司目录及原审批回调有依赖。下一步精简时先梳理关系，再移除；不应仅按“薪资”等文件名批量删除。

后续接入 Tegene 或其他统一平台，应替换身份和目录边界，映射角色与项目数据范围，并将文件、通知、审批事件接到平台接口。本轮不直接接入现有平台账号、生产数据或部署环境。


## 北京服务器独立部署（2026-09-30）

- 目标：北京 ECS `39.105.230.212`，独立 Compose 项目名 `aftersales`。
- 管理端：`https://sh.tegene.com/`；员工工作台：`https://sh.tegene.com/mobile/`。
- 生产使用 `LOGIN_MODE=password`；只初始化用户指定管理员，不导入本机数据库、演示人员或附件。密码仅通过初始化进程环境传入，不写入源码或文档。
- 源码版本在 `/srv/aftersales/releases/<commit>/`；`/srv/aftersales/current` 指向当前版本；生产环境配置 `/srv/aftersales/production.env`，权限 600。
- 独立 MySQL 实例、专用账号、会话密钥和三个持久卷。不复用 SCS、文档、舆情或 ERP 测试系统的数据与网络。
- `database` 网络只连接本系统 API 和 MySQL，并禁止外网访问；`application` 连接本系统 API/网页；`edge` 只连接售后网页与现有 OpenResty 入口。MySQL/API 不发布主机端口，网页诊断口仅绑定 `127.0.0.1:8180`。
- MySQL/API/网页分别限制为 0.75/0.75/0.25 CPU、768/768/128 MiB 内存；禁止额外交换内存，限制进程数；每容器日志最多 3 × 10MB。API 非 root、移除全部 capabilities，API/网页根文件系统只读。
- `deploy/storage.yaml` 将三个卷绑定到独立预分配 20 GiB ext4 文件系统 `/srv/aftersales/storage`，底层文件 `/srv/aftersales/data.ext4`。只在该文件系统内建立数据子目录，挂载失败时容器必须失败，不能回落写入宿主机根目录。容量接近上限时先安排备份与扩容。
- 仍共享宿主机内核、物理磁盘、网络和外层代理；不是故障完全隔离，也不是高可用部署。其他应用没有资源上限时仍可能争抢宿主机资源，完全隔离需要独立服务器。
- 前端与后端镜像在本机构建成 linux/amd64，再传到服务器加载；不在业务服务器运行编译。
- 新增域名的代理配置为 `deploy/edge.conf`；先 `nginx -t` 再平滑 reload，不重启其他容器。外层覆盖转发头，内部 API 仅信任隔离网络中的代理头，保留每 IP 登录限流。
- HTTPS 使用现有 Certbot 账户为 `sh.tegene.com` 单独签发证书；纳入现有每天续期任务，不修改其他域名证书。

生产启动：

```sh
cd /srv/aftersales/current
docker compose --env-file /srv/aftersales/production.env -f deploy/compose.yaml -f deploy/storage.yaml run --rm api python -m app.bootstrap
docker compose --env-file /srv/aftersales/production.env -f deploy/compose.yaml -f deploy/storage.yaml up -d --no-build --wait
```

验证：本地运行 `python3 scripts/test_deployment.py`；通过环境变量提供 `BASE_URL`、`ADMIN_PHONE`、`ADMIN_PASSWORD` 后运行 `python3 scripts/smoke_deployment.py`。首次空库验收增加 `EXPECT_EMPTY_INSTALL=1`。该脚本只登录和读取，不创建测试业务。另核对其他容器的 ID、启动时间、重启次数与原网站 HTTP 状态。

回退：仅停止 `aftersales` 项目，保留全部卷和 20 GiB 数据文件；切换到前一版本镜像与源码后启动。禁止执行全局 Docker 清理或对其他项目执行 down。域名代理需要撤回时，仅移走 `sh.tegene.com.conf`，验证 Nginx 配置后平滑 reload。
