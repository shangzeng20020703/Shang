# 现场轮休

适用于陪产日期由现场安排、默认上六休一的项目。固定时间上下班、自由上下班及原排班模式继续保留。

## 使用顺序

1. 在「项目库 → 配置项目」一次确认项目组长和全部组员的待配置名单。项目组长自动列入名单；此时人员不能按该项目打卡。
2. 从项目内打开个人排班，按北京时间周一至周日为组长及全部组员预览六上休一建议，逐人逐日修改，再确认至少一个共同未来周的安排。若另外确认了更多未来周，每周也必须包含当前完整名单。本周只确认今天至周日，未来周确认周一至周日。周期起点是第一天上班，第七天轮休，与星期无关。此时记录为“待规则生效计划”，不是正式打卡日，不计算工时或待休。
3. 待全员首周排班确认后，由有权管理该项目的区域组长或售后经理建立「现场轮休」规则，设置每日要求工时、考勤日开始时间、地点和照片要求。本模式不勾选星期，不允许选择工时不限制。首次保存规则时整份名单和计划统一校验；失败则保留待生效计划，成功后绑定规则快照并正式发布，向人员发送站内消息。规则生效日不得晚于将转为正式排班的最早未来日期；过期草稿只留审计，不转成历史考勤，若未来周不再完整，须先重新确认。
4. 规则正式生效后的排班变更由员工或负责人提交申请，按项目组长、区域组长、售后经理的顺序审核；组长改本人排班时跳过自己的审核节点。未发布日期不会因打卡而自动判为正常。
5. 在原定轮休日陪产，正常打上下班卡。员工申请事后出勤确认；完整打卡是确认前提。达到规则工时建议一天，达到一半建议半天，不足一半由售后经理说明原因后确认零或半天，最多一天。
6. 手机端可查看个人月历、申请调班或使用待休。调休只在原上班日使用，正常轮休不扣余额。半天调休将当天要求工时减半，不限制上午或下午时刻。

## 日期和余额口径

- 周期连续计算。例如连续陪产14天，原定第7天及第14天均为轮休；两天均满足工时并确认后，可得两天待休。
- 临时调班、正常轮休和已批准调休不自动重置后续周期。负责人可从未来日期重新生成周期，旧日历和调整日志保留。
- 人员调到另一项目后，新负责人可重新发布已完全结束旧项目参与关系的未来日期。旧项目尚未出勤的未来安排由新安排接替，前后内容留在审计日志；已有打卡、已批准调休及锁定月不自动覆盖。调动当天仍涉及旧项目时，从次日排班，当天实际打卡继续按项目分段留存。
- 公司节假日分类仍保留；现场是否需要上班按个人已发布日历判断。出勤产生的加班费仍沿用既有策略。
- 原定轮休日的自动加班转调休停用，由轮休确认流水入账；已有显式加班转调休来源会拦截轮休确认。反向重复转换也会拦截并进入既有事件失败诊断，需核对来源后处理。
- 待休以半天为最小单位，独立于旧假期余额记录，跨项目保留，不自动清零或过期。支出审批时扣减，撤销时退回，不可透支。两次并发审批也不能透支同一账户。
- 同一原定轮休日不能重复申请已批准或待审的出勤确认。批准后再更新下班卡或补卡，确认记录提示「打卡已变化，需复核」，原入账金额保留；须有原因地撤销后重新确认。已用额度导致余额不足时不能直接撤销来源。
- 员工不能直接修改正式排班或余额，只能提交申请；项目组长可安排所负责项目的人员及本人，区域组长可查看全部项目但只能修改被分配的项目，售后经理可管理全部项目。审批权限以项目根目录 README 为准。原定安排、规则快照、原因、操作人及账户流水保留。
- 显式调整会重算涉及日期，通过现有重算任务完成；不因新增规则自动重算历史。已锁定月份拒绝调整，须先按既有流程解锁。

## 接口与结构

`/api/v1/rotation` 提供 `GET /calendar`，`POST /projects/{id}/preview`、`/publish`、`/adjust`，`POST /claims` 和 `/claims/{id}/review`。规则前沿用预览和确认接口，但只写待生效计划；日历用 `draft_days` 与“待规则生效”状态展示。规则保存后才写正式排班。日历限366天，单次申请限62天，出勤确认逐日提交。确认要求预览返回的 revision；正式日期调整支持逐人日期版本检查。

原有四张独立表为 `field_rotation_days`、`field_rotation_claims`、`field_rotation_accounts`、`field_rotation_ledger`；schema 13 另新增 `field_rotation_draft_days` 保存规则前已确认的待生效计划，不改旧表列、不迁移旧调休余额。升级前备份，执行 `python -m app.bootstrap`；不能仅重启 API 跳过结构初始化。

回退前保留完整数据库备份及五张轮休相关表。旧版代码不能处理规则前待生效计划；已有轮休项目时不可直接用旧代码继续打卡。应先停止轮休业务写入，在隔离副本核对恢复点及此后新增记录，再制定切换步骤。源码版本副本不包含业务数据库。

## 验证

`backend/.venv/bin/python scripts/test_rotation.py` 使用临时SQLite库，覆盖真实打卡接口、周期预览及发布冲突、未排班待确认、事后确认、14天攒休、半天折算、缺卡及短时出勤、半天调休重算、重复审批、并发余额扣减、撤销、锁定月、跨夜、权限、日志及重开连接后的数据保存。完整检查入口为 `./scripts/check.sh`。测试数据不进入正式库或源码版本副本。
