# 原版 UI/UX 沿用与核对

基线：`Jaydon-Lidong/EHR@051b38f04b0e33f1e624da35fa57ecae9fd4974f`。按 2026-09-29 的补充要求，手机和管理端的打卡相关页面沿用 EHR 的界面结构与操作路径。此前简化的入口页面已恢复到原版组件，再接入售后业务。

## 1. 后续开发约束

- 优先修改原组件的数据接入、业务文案和角色范围；不要另造一套首页、导航、打卡或规则编辑器。
- 保留原版页面层级、底栏、返回栈、筛选、弹层、详情、异常处理、统计下钻及审批跳转。
- 新增客户、项目、现场和派驻入口接入原版工作台、快捷入口和管理端分组导航，采用原有颜色与卡片规范。
- 不因为拆分系统而删除打卡相关界面。原有考勤机未绑定状态也保留；它不代表已实现硬件接入。
- 定位、上传鉴权、照片必填、权限与草稿持久化等实际修复继续保留。
- “最近核验在场”、连续在场推断、定时复核仍后置；没有把这些操作加入页面。

| 管理端框架 | 原紫色侧栏、图标分组、折叠提示、面包屑、用户菜单、通知抽屉、窄屏遮罩 | 菜单接入项目与派驻、日志；个人资料与密码转入手机个人中心 |

| 手机打卡 | 上下班/外出切换、定位与地址选择、客户/备注/拍照/重拍预览、打卡按钮、成功反馈、当日记录、异常详情与申请入口 | GPS/IP 区分、未配置地图状态、必拍时沿用原图片行样式；移除截断地址中硬编码的“科创五街” |

| 手机通知 | 原搜索、全部/审批/通知分类、未读筛选、审批进展、已读与详情跳转 | 移除工资条分区，保留站内通知与审批交互 |

## 3. 比对与验证

`evidence/ui-source-comparison.json` 对 14 个核心页面/组件做源码比对，记录模板和样式是否与原版一致。14 个组件的样式块均与基线一致；管理端考勤页面模板、流程画布和节点组件，以及手机审批列表/详情/申请页模板也与基线一致。源文件行数差异主要来自导航范围、售后文案和接口适配，不能单凭行数判定功能完成度。

- `frontend/smoke.mjs`：两端登录和主要页面、三角色、模板草稿恢复；输出 `evidence/browser-smoke.json`。
- `frontend/ui-regression.mjs`：真实点击管理端标签、规则编辑、排班、报表、折叠与窄屏导航，以及手机快捷入口、弹层、底栏、工作台、打卡/申请/统计/规则详情/导出、档案和密码表单；输出 `evidence/ui-regression.json`。最终通过数量与失败项以该文件为准。
- `scripts/test_integration.py`：新增自助档案/假期接口与团队范围隔离的数据库验证；仍使用临时库。
- 截图在 `evidence/screenshots/`，包括管理端考勤、规则编辑和手机首页、外出、统计。

这些验证覆盖本地浏览器交互和已列出的业务接口。相机实拍、真实 GPS/Wi-Fi、弱网、外部地图服务与实体考勤机仍需实际环境验证；保留原界面不等于这些外部依赖已接通。
