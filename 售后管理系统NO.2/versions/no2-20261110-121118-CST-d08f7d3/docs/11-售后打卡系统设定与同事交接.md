# 售后打卡系统：业务设定与同事交接

> 整理日期：2026-11-09。本文记录目前确认的业务规则，以及当前源码提供的能力；“源码已实现”不等于正式站点已经部署或现场验收。具体项目、人员、排班和节假日在线配置可能随操作变化，以系统实时数据为准。

## 一页概览

售后打卡系统用于给现场人员按项目安排工作、打卡、处理异常和申请休息。项目资料可从 Tegene **只读**获取，也可导入项目地点表；售后人员、项目责任、个人排班、打卡和审批保存在售后系统自己的数据库中。管理员和 HR 是独立系统身份，现场业务职级依次为组员、项目组长、区域组长、售后经理。

**配置顺序：**项目库选择项目 → 售后经理分配主责区域组长（可另设协管）→ 确认一名项目组长及组员 → 为每个人单独确认排班 → 建立并保存该项目的现场轮休打卡规则 → 相关日期正式生效并通知员工 → 员工按当天唯一主项目的规则打卡。

规则保存前，已确认的人员和个人排班是**待生效**状态：员工可以看到项目与计划，但不能按该项目打卡，也不累计现场轮休额度。规则保存时整份名单和属于该项目的日期一起校验；任一人冲突，列明原因并保持待配置，不部分启用。尚未发布的后续日期显示“待确认”。

| 现场操作 | 组员 | 项目组长 | 区域组长 | 售后经理 |
|---|---|---|---|---|
| 查看项目 | 本人参与的项目 | 被任命的项目 | 全部项目，含人员与考勤明细 | 全部项目 |
| 管理人员和个人排班 | 无 | 所负责项目的组员及本人 | 主责、协管项目 | 全部项目 |
| 新建、修改项目打卡规则 | 无 | 无 | 主责、协管项目 | 全部项目 |
| 分配项目组长和组员 | 无 | 无 | 主责、协管项目 | 全部项目 |
| 分配区域组长负责项目 | 无 | 无 | 无 | 可以 |
| 审批请假、出差、攒休、调休 | 无 | 无 | 无 | 全部售后人员 |
| 本人打卡 | 需要 | 需要 | 不需要 | 不需要 |

系统管理员可跨项目管理、任命售后经理，并可在写明原因后代审经理本人或经理缺席时的申请。HR 可查看原有管理资料和节假日表、维护全局共用规则模板，不进入上述四类申请的日常审批链。旧全局 `manager` 角色不等于售后经理，也不自动获得售后项目管理或审批权限。页面隐藏按钮之外，服务端也校验角色及项目范围。

## 项目与人员怎样配置

1. **建立项目。** Tegene 接口保持只读；本系统还可在“项目库 → 导入项目与打卡位置”上传 Excel，只读取“项目编号、项目名称、地理位置、是否需要定位”四列。以项目编号识别同一项目，先预览差异再确认，重复导入不生成同号项目。导入名称优先作为售后页面显示名。项目进入库后即可配置，客户资料可稍后补录。项目库每页显示 50 行。
2. **确定责任范围。** 售后经理给项目指定一位主责区域组长，可增加协管；区域组长仍能查看所有项目，但只能修改自己主责或协管的项目。每项目同时只有一位项目组长。
3. **确认人员名单。** 项目配置中的组长选择框只显示在职“项目组长候选”，组员选择框只显示在职“组员”，区域组长选择框只显示具有区域组长角色的人。候选标记本身不授予项目管理权限；组长获具体项目任命后才有相应入口。组长和组员用一次“确认人员配置”保存，组长自动加入名单；规则建立前可再次确认替换待配置组员，已有个人计划须先处理。
4. **逐人确认排班，再建规则。** 每名组员和组长分别选起始日期、周期与每日安排，至少确认一个完整周期。之后由有权管理该项目的区域组长或售后经理保存现场轮休规则，系统启用人员和属于该项目的计划日期。人员、排班或规则未生效时，不能按该项目打卡。

员工每天只有**一个主项目**。项目 1 结束后转到项目 2，可以按连续日期安排，个人轮休进度随人延续。跨区域的未来项目调动须原项目方和接收方分别确认；历史项目归属、原定轮休日、规则快照及已产生的打卡保留。白班、夜班只是可选展示标签，实际工时按当天项目规则核算。未来尚未确定项目的日期可以先标“待分配项目”，但不能据此打卡。

## 个人排班与现场轮休额度

现场轮休不需要勾选固定的周一至周日工作日。每个人可独立采用“上 6 休 1”“上 12 休 2”“上 18 休 3”或自定义逐日排班，原因默认“周期排班”；自定义至少确认 7 天。排班起点和日期可因人而异，临时休息、使用额度或更换现场轮休项目都不清零累计进度。固定工作日、原排班和自由上下班规则仍可由项目选择使用。

- 当天按主项目规则打齐上下班卡且满足要求工时，计 **1 个有效工作日**；达到一半、未满全天工时，须售后经理确认后才计 **0.5 日**。缺卡、低于一半或未确认的异常不计。获批出差还须经理确认实际工作；同一日期最多计 1 日，不与已有加班转调休来源重复累计。
- 每累计 **6 个有效工作日**获得 **1 天现场轮休额度**，不足 6 天的进度继续保留。例如上 8 天获得 1 天、余 2 天进度；休 1 天后再上 4 天，获得下一天。
- 常规上 6 休 1 的休息日，余额足够时自动扣 1 天；延后或集中休息由员工申请、售后经理审批后扣除。支持半天，不允许余额透支。可预先排尚未攒够额度的休息，但显示“待兑现”；到期仍不满足时显示“待处理”，不会自动判为正常休息或旷工。
- 额度入账、使用、撤销及补卡后的调整有流水。来源变化而额度已使用时须人工核对，不能静默删除历史。新滚动算法由管理员设置生效日期，既有余额与历史考勤不追溯重算。

参与现场轮休的员工在手机端可看“现场轮休可用额度”及“我的排班与待休”，其中分别显示余额、累计进度、待确认出勤、待兑现休息、个人日历和流水；余额为零也显示 0 天。该额度与原有“调休余额”分别标注，员工只能查看和申请本人事项。

**审批路径：**正式发布后的排班变更依次由项目组长、区域组长、售后经理审核；组长调整本人排班时跳过自己的节点。涉及多个项目时，各相关项目的组长和区域组长先审核，再由经理决定。请假、出差、攒休、调休直接由售后经理统一审批；跨项目申请按日期记录项目和考勤影响，但不拆成多个区域审批单。任一必需节点驳回，整单不生效。

## 打卡规则、地点与节假日

员工按当天主项目自动读取打卡规则，不必自行选项目。现场轮休规则必须设置具体的每日要求工时，不能选“不限制”；另可设置考勤日开始时间、地点、定位和照片等要求，跨夜打卡按规则的考勤日划分。其他自由工时规则若设置具体时长，即使上下班卡齐全，实际工时不足仍标“异常”并说明差额；只有这类规则选择“不限制”时才不做最低工时校验。规则修改只影响后续新打卡，历史记录保留当时的项目和规则快照。区域组长修改共用规则时，系统为该项目生成专用版本，不连带改变其他项目。

**照片与定位是两项独立要求。** 规则开启“每次打卡均需拍照”时，人在打卡范围内也须拍照；未开启时不因定位范围本身强制拍照。项目地点是允许打卡的范围，实际打卡记录保存员工当时的定位结果，不把项目名称硬写成实际位置。

项目表标为“需要定位”且含有效腾讯地图坐标时，新规则预填该地点和 **300 米**半径，负责人可在规则中修改。只有地点文字、没有有效坐标时，须先在规则内手动设置打卡范围；服务端会拒绝保存无有效范围的定位规则，也不会放行缺少范围的定位打卡。“不需要定位”只关闭 GPS 要求，照片、Wi-Fi 等其他要求仍取决于规则。已生效规则不会被再次导入的地点静默改变；变更须先看差异并确认，手工地点及历史记录保留。

2026 年节假日**初始模板**来自公司提供的 11 行表，不使用国务院放假、补班预设。未列日期按普通工作日或周末判断。星期由日期自动算出，日期类型固定为“法定节假日”；管理员可在“考勤管理 → 考勤规则 → 节假日表”在线增删日期、修改名称，HR 只读。在线表格若已修改，以当前配置为准；修改过去日期不自动重算历史考勤。

## 账号、企微和地图配置边界

- **本机开发。** 默认开发服务使用本机 SQLite 和回环地址，只有明确启用开发免密码开关时，账号或本机演示短工号才可免密码登录；该能力不能用于正式环境。默认开发端口为管理端 `5186`、手机端 `5187`、API `8186`。独立项目地点预览使用 `5386`、`5387`、`8386`，与默认开发库不是同一套数据。演示人员、项目操作和数据库仅保留在 Git 忽略的本机运行目录，人数及分配情况会随测试变化。
- **正式账号。** 在职且启用的员工按花名册手机号开户并使用密码登录，离职或停用后不能继续使用；初始密码由管理员通过安全渠道通知。企业微信登录与工作台接入须在企业配置和真实成员上另行验证，不能把本机免密码登录当作正式方案。
- **企业微信工作台。** 目标卡片名称为“售后打卡系统”，图标仅用定位元素，不用 Tegene 的 T 标志；预期手机主页为 `https://sh.tegene.com/mobile/`。卡片、可见范围、可信域名和应用身份由企业微信管理员在后台核对与配置；仓库中的图标文件或网页名称变更不会自动修改企业微信卡片。
- **腾讯地图。** 浏览器地图 Key 供手机端地图 SDK 使用，后台保存值优先于服务器环境变量 `TENCENT_MAP_BROWSER_KEY`，清除后台覆盖值后回退。当前源码仅有管理员专用的配置接口，管理端没有公开配置页面。后端坐标转换和逆地址解析使用独立的 `TENCENT_MAP_WEB_SERVICE_KEY`，不下发浏览器。Key 应放在受控部署配置中，浏览器 Key 需在腾讯控制台限制实际域名；真实手机定位和拍照应在可达 HTTPS 环境验收。

## 已取代的旧说法

- “区域组长只能看分配项目”已改为**能看全部项目，只能修改主责、协管项目**。
- “区域组长审批请假、出差、攒休、调休”已改为**售后经理统一审批**；跨项目请假、出差也不按项目拆单。
- “项目负责人可直接修改已发布排班”已改为**组长、区域组长、售后经理逐级审核**。
- “现场轮休先建立打卡规则再排班”已改为**先确认人员、逐人确认完整排班，再保存规则使之生效**。
- “节假日跟随国务院调休表”已改为**公司在线维护的年度日期表**。
- “导入项目必须补齐客户资料才能配置”已取消；客户资料可稍后补录。
